Critical Button missing accessible name
Fix this first — blocks 2 other checks New
▸

Buttons must have discernible text that identifies their purpose. Screen readers announce this element as "button" with no additional context, making it impossible for users relying on assistive technology to understand its function.

WCAG 2.1: 4.1.2 Name, Role, Value (Level A)

File: packages/button/src/Button.tsx, Line 42

<button className={styles.icon} onClick={onClose}> <CloseIcon /> </button>

Add an aria-label attribute describing the button's action:

<button className={styles.icon} onClick={onClose} aria-label="Close dialog"> <CloseIcon /> </button>

Serious Focus not trapped inside modal dialog
Complex fix New
▸

When a modal dialog is open, keyboard focus can escape to elements behind the overlay. This can cause users to interact with hidden content or get lost on the page.

WCAG 2.1: 2.4.3 Focus Order (Level A)

File: packages/modal/src/Modal.tsx, Line 28

<div className={styles.overlay}> <div className={styles.modal} role="dialog"> {children} </div> </div>

Implement a focus trap using aria-modal="true" and manage focus with a focus-trap utility:

<div className={styles.overlay} onClick={onClose}> <div className={styles.modal} role="dialog" aria-modal="true" ref={trapRef} > {children} </div> </div>
